Async JavaScript Made Simple

Understand async, await, Promise.all(), Promise.race(), new Promise() and callbacks — with practical examples and a QA/automation mindset.

1. The Big Picture

JavaScript often starts an operation that finishes later — for example, an API request, file operation, timer or browser action. Instead of blocking everything while waiting, JavaScript can continue with other work and handle the result when it becomes available.

Callback

“Call this function when the work finishes.”

Promise

“I represent the future result of this operation.”

async

Makes a function return a Promise.

await

Waits for a Promise inside an async function.

2. Callback

A callback is a function passed to another function so it can be called later, usually when an operation completes.

function getData(callback) {
  setTimeout(() => {
    callback("Data received");
  }, 1000);
}

getData((result) => {
  console.log(result);
});

Flow: Start task → task completes → callback runs.

Watch out: many nested callbacks can become difficult to read and maintain (“callback hell”). Promises provide a cleaner model for many asynchronous workflows.

3. new Promise()

The Promise constructor creates a Promise. Its executor receives two functions: resolve for success and reject for failure.

function getData() {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      const success = true;

      if (success) {
        resolve("Data received");
      } else {
        reject(new Error("Something went wrong"));
      }
    }, 1000);
  });
}

getData()
  .then(data => console.log(data))
  .catch(error => console.error(error));
Important: new Promise() is mainly useful when you need to create a Promise around an API that does not already provide one, such as a callback-based API. If an API already returns a Promise, you normally do not need to wrap it in another Promise.

4. async

Putting async before a function makes it an async function. An async function always returns a Promise.

async function getUser() {
  return "Kavita";
}

console.log(getUser()); // Promise

The returned Promise fulfills with "Kavita".

5. await

await is used to wait for a Promise to settle and gives you its fulfillment value. It is normally used inside an async function (with top-level await also available in JavaScript modules).

function getData() {
  return new Promise(resolve => {
    setTimeout(() => resolve("Data received"), 1000);
  });
}

async function test() {
  console.log("Start");

  const data = await getData();

  console.log(data);
  console.log("End");
}

test();

Flow: Start → await Promise → Promise fulfills → continue → End.

Key idea: await pauses the execution of the current async function at that point; it does not freeze the entire JavaScript runtime.

6. Promise.all()

Use Promise.all() when multiple asynchronous tasks can run concurrently and you need all of them to succeed.

const api1 = fetch("/users");
const api2 = fetch("/products");
const api3 = fetch("/orders");

const [users, products, orders] =
  await Promise.all([api1, api2, api3]);

All three operations can be started without waiting for one another. The returned Promise fulfills with results in the same order as the input. If any input Promise rejects, Promise.all() rejects.

QA example: Fetch user details, product details and order details independently, then continue only after all three responses are available.

7. Promise.race()

Promise.race() settles when the first input Promise settles — whether it fulfills or rejects.

const fast = new Promise(resolve =>
  setTimeout(() => resolve("Fast response"), 1000)
);

const slow = new Promise(resolve =>
  setTimeout(() => resolve("Slow response"), 3000)
);

const result = await Promise.race([fast, slow]);

console.log(result); // Fast response

Flow: Start multiple tasks → first one settles → race result settles.

Practical use: Implement a timeout by racing an API request against a timer that rejects after a limit.
const response = await Promise.race([
  fetch("/api/data"),
  new Promise((_, reject) =>
    setTimeout(() => reject(new Error("Timeout")), 5000)
  )
]);

8. Promise.all() vs Promise.race()

FeaturePromise.all()Promise.race()
Waits forAll inputs to fulfillFirst input to settle
If one rejectsResult rejectsResult rejects only if the first settled input rejects
Typical useMultiple required API callsTimeout / first-response scenarios
ResultArray of fulfillment valuesValue/reason from the first settled input

9. Sequential vs Concurrent Async Code

Sequential

const user = await getUser();
const orders = await getOrders();
const products = await getProducts();

Each call waits for the previous one. This is correct when the operations depend on one another, but unnecessary waiting can occur when they are independent.

Concurrent

const [user, orders, products] = await Promise.all([
  getUser(),
  getOrders(),
  getProducts()
]);

Independent operations are started together, and the code waits for all required results.

12. One Example Combining Everything

function getTestData() {
  return new Promise(resolve => {
    setTimeout(() => resolve("Test data ready"), 1000);
  });
}

function getEnvironment() {
  return new Promise(resolve => {
    setTimeout(() => resolve("QA environment ready"), 1500);
  });
}

async function runTestSetup() {
  console.log("Starting setup...");

  const [data, environment] = await Promise.all([
    getTestData(),
    getEnvironment()
  ]);

  console.log(data);
  console.log(environment);
  console.log("Setup complete.");
}

runTestSetup();

This pattern is especially useful in test automation when independent setup tasks can run concurrently.
